## Requirements summary

v1.2 两主线：**AI 翻译增强**（术语表/人名表、批间上下文、断点续传、译文润色）与 **Whisper 转写加速**（faster-whisper 后端、whisper.cpp/GPU 评估推荐、转写后处理 VAD+初始提示词模板）。全部基于现有 `TranslationService`（30 cue 批次 + 2 次重试）与 `WhisperService`（openai-whisper CLI）增量演进。

## Acceptance criteria

- AC-1 术语表注入：`translateSystemPrompt` 接收术语表，生成「原文→译文」锁定段；译文留空的条目生成「do not translate」指令
- AC-2 术语表 UI+持久化：翻译页可增删改查术语条目，存 settings JSON，任务执行时读取注入；上限 200 条并提示
- AC-3 批间上下文：第 N 批（N≥2）请求携带前批尾部 3 条「原文+已译文」作为上下文；首批无上下文；响应契约不变（纯 JSON 数组）
- AC-4 断点续传：失败批次重跑同任务时，已成功批次不再发起 HTTP 请求（fake client 请求计数断言）；checkpoint 校验 cueCount+inputMtime+lang 全部一致才复用，任一不符丢弃重来
- AC-5 取消/成功语义：取消（含批间检查）保留 checkpoint；全部成功写完产物后删除 checkpoint
- AC-6 润色模式：开启时翻译后二阶段调用（仅断句/标点/口语优化、不改语义、保留 ASS 标签与 `\N`）；关闭时零额外请求
- AC-7 Whisper 后端：设置页后端选择（自动/whisper/faster-whisper）；faster-whisper 走 `whisper-ctranslate2` CLI；`buildArgs` 按后端差异化（faster+CPU 用 `--compute_type int8` 替代 `--fp16 False`）
- AC-8 GPU 自动推荐：检测 `nvidia-smi` 可用 → Whisper 页 GPU 选项默认勾选（用户可改）
- AC-9 VAD 静音过滤：faster-whisper 后端时转写页提供 VAD 开关（`--vad_filter true`）；openai-whisper 后端该开关禁用并说明
- AC-10 初始提示词模板：Whisper 页可填初始提示词（透传现有 `--initial_prompt`），支持 `{episode}` 占位符从文件名自动提取集数（如 `Show - 12 [1080p].mkv` → `12`）
- AC-11 whisper.cpp 评估交付：设置页 Whisper 区块注明评估结论（whisper.cpp 无 Python 依赖、分发友好，但 CLI 参数面与 GUI 集成成本高，v1.2 暂不集成，推荐 faster-whisper）——交付物为结论文案，非集成
- AC-12 质量门禁：`dart analyze` 零问题；`flutter test` 全绿（新增行为先红后绿）；翻译页/Whisper 页三档窗口无 RenderFlex 溢出

## RALPLAN-DR

### Principles

- 最小代码：复用现有批次/重试/`_chat`/`_parseArray` 管线，新能力以参数与独立小函数加入，不重构服务
- 外科手术式改动：只动翻译/Whisper 链路 6 个文件 + 2 个页面 + settings，不碰队列调度与 mux
- 不假设：whisper-ctranslate2 的参数面以官方 README 为准（drop-in 兼容 openai-whisper + `--vad_filter`/`--compute_type`）；CPU 参数差异在后端分支内显式处理
- 可验证成功标准：每条 AC 有对应单测（prompt 构造、checkpoint 读写、buildArgs 差异、episode 提取）或 UI 测试

### Decision drivers

1. **正确性优先**：断点续传与术语表直接影响产物质量，错译/重译不可接受
2. **最小 token 成本**：批间上下文与术语表注入都控制尺寸（尾部 3 条 / 术语 200 条上限）
3. **与现有架构一致**：设置项走 SettingsProvider，任务参数走 TaskParams 字符串表，UI 状态走 ValueListenableBuilder

### Viable options

**Option A: 术语表存应用级 settings JSON（chosen）**
- 实现思路：`SettingsProvider` 增 `glossary` 列表（{原文,译文}），翻译页对话框编辑，运行时注入 prompt
- 改动文件：`settings_provider.dart`、`translation_service.dart`、`translate_screen.dart`
- Pros: 无新文件管理概念，改动最小；Cons: 「项目级」弱化为「应用级」（本应用无项目概念，语义上等价于用户词库）

**Option B: 术语表存字幕旁车文件（.glossary.json）**
- Pros: 真「项目级」随片走；Cons: 引入旁车文件生命周期管理（丢失/错配/清理），UI 与队列都要感知文件存在，改动面翻倍
- **Invalidation rationale**: 应用无项目/工作区概念，旁车文件解决的「多人共享词库」场景本版本不存在，成本收益不成立。列入 Follow-ups

**Option C: 断点续传 checkpoint 旁车（chosen，针对 AC-4/5）**
- 实现思路：`<输出路径>.progress.json` 记 {version, cueCount, inputMtimeMs, lang, batches:[[译文..]..]}；每批成功后落盘；启动时校验复用；成功后删除；文件名加 `.` 前缀降低可见度
- 改动文件：`translation_service.dart`（新增 `TranslateCheckpoint` 小类）、`task_runner.dart`（传 checkpoint 路径）
- Pros: 跨应用重启可恢复、批次粒度精确；Cons: 输出目录多一个临时文件（成功即删，失败保留属预期）

**Option D: 断点续传存内存（rejected）**
- **Invalidation rationale**: ROADMAP 明确「取消后可恢复」含跨会话场景；内存方案应用重启即失，直接不满足需求

**Option E: Whisper 后端单服务+后端枚举（chosen，针对 AC-7..9）**
- 实现思路：`WhisperService` 增 `WhisperBackend {auto, openai, faster}`；检测顺序按偏好探测 `whisper` / `whisper-ctranslate2`；`buildArgs` 增 backend 参数分支
- 改动文件：`whisper_service.dart`、`settings_provider.dart`、`whisper_screen.dart`、`settings_screen.dart`
- Pros: 复用进度解析（verbose 时间戳行两家 CLI 输出一致）、模型下载、GPU 参数；Cons: buildArgs 分支增多（用单测钉死）

**Option F: FasterWhisperService 独立类（rejected）**
- **Invalidation rationale**: 进度解析/超时/取消/模型管理 100% 重复，只有 args 构造差 ~6 行；独立类是 premature abstraction

### Implementation steps

1. **术语表模型+prompt 注入** — `translation_service.dart`：`translateSystemPrompt(target, {glossary})` 增锁定段；`GlossaryTerm` 类（20 行）；`_translateBatch` 透传 — 测试 `translate_prompt_test.dart` 扩展
2. **术语表持久化** — `settings_provider.dart`：`glossaryTerms`（List<Map>）读写 settings JSON；上限 200
3. **术语表 UI** — `translate_screen.dart`：设置区加「术语表」按钮 → 对话框表格（原文/译文/删除/新增）；`task_runner.dart:382` 运行时读取注入
4. **批间上下文** — `translation_service.dart:_translateBatch`：增 `context` 参数（前批尾部 3 条 (src,trans) 对），user payload 变 `{context?, lines}` 双字段；`translateDocument:119` 循环里滚动维护 — 测试断言第 2 批 payload 含第 1 批尾部、首批无 context 字段
5. **checkpoint** — `translation_service.dart`：`TranslateCheckpoint`（save/load/validate/delete，JSON）；`translateDocument` 增 `checkpointPath` 参数，每批成功 append+落盘，启动时 load+validate 复用已译批次，成功后 delete — 测试：fake `_chat`（子类注入）计数复用批次、取消保留、成功删除、mtime 不符丢弃
6. **润色模式** — `translation_service.dart`：`polishSystemPrompt()` + `polishDocument()`（复用 `_chat`/`_parseArray`/批间取消检查）；`task_runner.dart:_runSubtitleTranslate` 翻译后按 `TaskParams.polishMode` 二阶段，进度 0.95→1；`translate_screen.dart` 加开关 — 测试 prompt 规则 + 关闭时零请求
7. **Whisper 后端枚举+检测** — `whisper_service.dart`：`WhisperBackend` 枚举 + `_tryCommand` 探测 `whisper-ctranslate2`；`settings_provider.dart` 增 `whisperBackend` 偏好；`settings_screen.dart` Whisper 区块加下拉 + whisper.cpp 评估结论文案（AC-11）
8. **buildArgs 后端分支** — `whisper_service.dart:557`：backend 参数；faster+CPU → `--compute_type int8`（去 `--fp16 False`）；单测钉死两种后端 × CPU/GPU 的 args
9. **GPU 自动推荐** — `whisper_service.dart`：`detectNvidiaGpu()`（`nvidia-smi -L` exit 0）；`whisper_screen.dart` GPU 开关初始值 = 检测结果（用户手动改过后尊重手动值）
10. **VAD 开关** — `whisper_screen.dart`：faster 后端时启用 VAD 勾选（默认开），openai 后端禁用+提示；`task_runner.dart:_runWhisper` 透传 `vadFilter` → `buildArgs` 追加 `--vad_filter true` — 单测 buildArgs
11. **初始提示词模板** — `whisper_screen.dart`：提示词输入框 + `{episode}` 说明；`whisper_service.dart`：`expandInitialPrompt(template, inputPath)` 提取集数（文件名中 ` - 12 ` / `EP12` / `第12话` 常见模式）；`task_runner.dart` 运行时展开 — 单测提取规则
12. **质量门禁** — 全量 analyze + test + 翻译/Whisper 页三档布局测试

### Workspace setup

- `git status`：**项目非 git 仓库**（无版本控制）。worktree 流程不适用；护栏 = 每步 TDD + 全量测试门禁。已与现状确认。

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| whisper-ctranslate2 实际参数面与假设不符（`--vad_filter`/`--compute_type` 拼写或版本差异） | buildArgs 单测钉死本侧契约；CLI 报错原文进任务日志（错误详情可复制已就绪）；设置页注明「需 pip install whisper-ctranslate2」 |
| checkpoint 与 dedupe 后输出路径错配（任务重跑时 output 变 `_1`） | checkpoint 路径由 task_runner 按本次任务 output 派生；mtime/cueCount 校验兜底，不符即弃 |
| 术语表过大撑爆 token | 硬上限 200 条 + UI 计数提示 |
| 批间上下文污染响应解析（模型把 context 译出来） | context 放 user payload 独立字段 + system prompt 明示「translate ONLY the lines array」；`_parseArray` 契约不变 + 长度校验回退原文已有 |
| nvidia-smi 存在但 torch 无 CUDA → 转写失败 | GPU 仅作默认建议可手改；失败时任务错误信息已含 CLI 原文 |
| 润色二阶段改变译文语义 | prompt 锁定「meaning-preserving」；用户开关默认关 |

## ADR

- **Decision**: 翻译增强全部内嵌现有 `TranslationService`（prompt 扩参 + checkpoint 旁车 + 二阶段润色）；Whisper 后端用单服务枚举分支接入 `whisper-ctranslate2`；whisper.cpp 只交付评估结论不集成。
- **Drivers**: 正确性优先、最小 token 成本、架构一致性（三项全部起决定作用）
- **Alternatives considered**: 术语表旁车文件（rejected：无项目概念）、断点续传内存态（rejected：不满足跨会话恢复）、FasterWhisperService 独立类（rejected：100% 重复）
- **Why chosen**: 所有能力都能以「参数 + 小函数」落进现有管线，唯一新增持久化是 checkpoint 旁车（需求强制）；Whisper 单服务枚举把差异压缩到 buildArgs 一处。
- **Consequences**: `translateSystemPrompt` 签名变更（内部唯一调用方+测试同步）；checkpoint 在输出目录留临时文件（成功即删）；whisper.cpp 集成推迟到 v1.5+ 评估再议。
- **Follow-ups**: 术语表旁车文件化（真项目级词库共享）；whisper.cpp 集成评估；润色模式的「自定义润色指令」。
