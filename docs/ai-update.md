目前项目 AI 能力：翻译（SSE 流式+思考直播）、润色二阶段、术语表、断点续传、测试连接+模型下拉、Whisper 三后端转写。基于现状，以下是可行的优化方向，按投入产出分层：

**一、快赢项（1 个行为/小时级）**

| 优化点 | 说明 |
|---|---|
| JSON 输出模式 | 请求加 `response_format: json_object`，减少「模型输出非 JSON→重试」的失败率（重试即重复计费） |
| 流式译文上屏 | 现在 `content` delta 已解析但只在批完成时显示预览；可让当前批次译文逐字上屏，直播面板更“活” |
| token 用量统计 | 从 SSE 尾包 `usage` 读取，任务结束显示本次消耗 token / 预估费用 |
| 失败批次拆分重试 | 某批失败时自动切半重试（30→15→8 条），长批次解析失败的主要救星 |

**二、中等项（结构性增强）**

1. **多配置档案**：OpenAI / DeepSeek / 中转站多套配置一键切换，不用反复改单条配置；也可做主备自动切换（主模型 5xx 时降级到备用）。
2. **翻译内容缓存**：行文本哈希 → 译文缓存（本地 SQLite/JSON），重跑失败任务、翻译相似文件（同剧集不同集数片头）零成本命中。
3. **提示词模板可配置**：翻译/润色系统提示词目前硬编码，做成可编辑预设（动漫腔、正式、科普等风格档）。
4. **超时/重试/并发参数可调**：120s 超时、2 次重试目前是常量，设置页暴露。
5. **推理成本控制**：reasoning 模型的 `reasoning_effort` / `max_tokens` 配置，思考流看着爽但 token 烧得快。

**三、智能功能项（新场景）**

6. **AI 断句修复**：Whisper 转写常见“半句截断/一行超长”，用 AI 按语义重排断句——这是转写用户最痛的点。
7. **术语自动提取**：转写完成后 AI 自动扫出人名/专名生成术语表候选，人工确认后入表。
8. **全局剧情上下文**：现在批间只带前 3 条上下文；先生成一份剧情摘要注入所有批次，长字幕人名一致性显著提升。
9. **转写→断句→翻译一键管线**：把三个 AI 任务串成预设流水线，拖入视频出双语成片字幕。

我的建议：下一版先做 **一全部 + 二的 1/2**（性价比最高），「AI 断句修复」作为 v2.3 的主打特性单独立项（场景最刚需、演示效果最好）。想先推进哪个方向，我来出实施方案。
